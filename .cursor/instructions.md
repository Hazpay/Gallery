# Инструкции по работе с ИИ-ассистентом в проекте

## 🚀 Обязательный стартовый промт для каждой новой сессии

**Копируйте и вставляйте этот промт в начало каждой новой переписки с Cursor:**

```
Перед тем, как начать работу, прочти CURRENT_STAGE.md и все файлы, на которые он ссылается, по порядку.

Затем, выпиши кратко наши задачи и я дам команду для следующего шага.
```

Этот промт позволит ИИ-ассистенту быстро понять текущий контекст проекта без необходимости читать всю историю переписки.

---

## 📝 Правила обновления CURRENT_STAGE.md

### Когда обновлять:
- После каждого значимого шага или завершения задачи
- При переходе к новому этапу работы
- При изменении приоритетов или планов
- Когда начинаете работу над новой функциональностью

### Что обновлять:
1. **Текущий этап проекта** — краткое описание того, на каком этапе вы находитесь
2. **Выполненные шаги** — добавьте новый выполненный шаг в начало списка, удалите самый старый, если шагов больше 10
3. **Текущие задачи** — обновите статус задач (отмечайте выполненные, добавляйте новые)
4. **Ближайшие планируемые шаги** — скорректируйте план на основе выполненных задач
5. **Референсы на релевантные файлы** — обновите список, оставив только актуальные для текущего этапа файлы

### Пример обновления:

**До:**
```markdown
## 🎯 Текущие задачи (приоритетные)
- [ ] Реализовать функцию X
- [ ] Исправить баг Y
```

**После:**
```markdown
## 🎯 Текущие задачи (приоритетные)
- [x] Реализовать функцию X ✅ (завершено 10.12.2025)
- [ ] Исправить баг Y
- [ ] Добавить тесты для функции X
```

## 📚 Как добавлять новые файлы в модульную документацию

### Структура директории `.cursor/`:

```
.cursor/
├── instructions.md          (этот файл)
├── architecture.md          (описание архитектуры проекта, если нужно)
├── api-reference.md         (описание API, если есть)
├── components.md            (описание компонентов, если нужно)
├── troubleshooting.md       (решения частых проблем)
└── ...
```

### Правила создания новых файлов документации:

1. **Название файла** — используйте понятные названия на английском языке в нижнем регистре с дефисами
2. **Структура файла** — используйте markdown с заголовками для навигации
3. **Связь с CURRENT_STAGE.md** — добавьте ссылку на новый файл в раздел "Референсы на релевантные файлы", когда он станет актуальным

### Пример создания нового файла документации:

Если вы создали файл `.cursor/api-reference.md`, добавьте в `CURRENT_STAGE.md`:

```markdown
## 📎 Референсы на релевантные файлы
- `index.html` - основной файл галереи
- `.cursor/api-reference.md` - описание API для работы с изображениями
  - *Зачем нужен сейчас:* работаем над интеграцией с внешним API
```

## 🔗 Как ссылаться только на нужные файлы в CURRENT_STAGE.md

### Принцип минимализма:
- **НЕ** добавляйте все файлы проекта
- **ДОБАВЛЯЙТЕ** только те файлы, которые:
  - Активно используются в текущих задачах
  - Содержат критическую информацию для понимания контекста
  - Будете часто упоминать в ближайшее время

### Формат ссылки:
```markdown
- `путь/к/файлу` - краткое описание файла
  - *Зачем нужен сейчас:* конкретная причина, почему этот файл важен для текущего этапа
```

### Пример хорошего раздела референсов:
```markdown
## 📎 Референсы на релевантные файлы
- `index.html` - основной файл галереи, содержит HTML, CSS и JavaScript
  - *Зачем нужен сейчас:* работаем над добавлением новой функциональности просмотра
  
- `.cursor/instructions.md` - инструкции по работе с ИИ
  - *Зачем нужен сейчас:* настраиваем систему контекста проекта
```

### Когда убирать файлы из референсов:
- Задача, связанная с файлом, завершена
- Файл больше не используется в текущих задачах
- Переходите к новому этапу, где этот файл неактуален

## 💡 Дополнительные рекомендации

### Экономия токенов:
1. Регулярно обновляйте `CURRENT_STAGE.md` — это поможет начать новую сессию без чтения всей истории
2. Используйте краткие, но информативные описания
3. Удаляйте устаревшие ссылки из референсов
4. Если переписка стала слишком длинной, можете начать новую сессию, указав ИИ прочитать `CURRENT_STAGE.md`

### Поддержание актуальности:
- Обновляйте `CURRENT_STAGE.md` в конце каждой сессии работы
- Делайте это привычкой — так вы всегда будете иметь актуальный контекст
- Периодически проверяйте, что референсы соответствуют текущим задачам

### Работа с большими проектами:
- Разбивайте сложные задачи на этапы, отражая их в `CURRENT_STAGE.md`
- Создавайте отдельные файлы документации в `.cursor/` для разных аспектов проекта
- Ссылайтесь на них в `CURRENT_STAGE.md` по мере необходимости
